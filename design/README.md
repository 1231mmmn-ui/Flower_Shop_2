## 空間の設計にある、たった一つの考え

**10の画面を「別々のページ」にしない。**

ひとつの花屋の中で、**カメラが動くだけ**にします。

```
入口から店を見る  →  カウンターへ寄る  →  花に寄る  →  一輪だけを見る
      ①②                  ③④                ⑤             手元へ ⑥⑦⑧
```

こうすると、

- 画面が切り替わっても、プレイヤーは花屋から一度も出ない
- 遷移の演出が「カメラ移動」と「ピント送り」の2つだけで決まる
- どの画面を開いても、最初に目に入るのは花か店内になる

という3つが同時に満たされます。

## 全画面に共通する、破らない3つの決めごと

### 1. 画面中央は「花の間（はなのま）」。UIを置かない

画面を縦に3つに分けます。

```
 0% ┌────────────────────────┐
    │  空の帯   季節・日／しるし   │  ← UIを置いてよい（最小限）
14% ├ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ┤
    │                        │
    │      花 の 間           │  ← ここにUIを置かない
    │  （花・店内・お客さま）    │     画面の 58% は花と店内のもの
    │                        │
72% ├ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ┤
    │  手の帯   ことば／ボタン    │  ← UIを置いてよい
100%└────────────────────────┘
```

例外はひとつだけ。**⑤花詳細で下から上がってくる紙**は、花の間の下端に少しかかります
（花を見上げる姿勢を作るため）。それ以外に例外は作りません。

### 2. 面（パネル）を置く前に、光で読ませる

文字が読みにくいとき、まず**その文字のうしろに光をにじませます**。
それでも読めないときだけ、紙一枚を置きます。半透明のパネルを増やしません。

1画面に置いてよい紙は **1枚まで**。

### 3. 主ボタンは1画面に1つ

迷わせないためではなく、**画面を静かにするため**です。
2つ目からは、面を持たない下線付きの文字にします。

## レビューでご確認いただきたいこと

**感情について（最優先）**

1. 山をふたつ（**発見**と**感動**）に絞る配分でよいか
2. **⑥⑦を意図的に「谷」にする**こと。手を動かす時間に演出を足さない方針でよいか
3. **呼応表と呼応セリフ8行**（11-emotion.md 4章）。ここがこのゲームの心臓です
4. 再訪したお客さまが前回に触れる案を入れるか（長く遊ぶ理由として最も強いと考えています）

**空間について**

5. 「カメラが動くだけ」という考え方でよいか
6. 花の間 58% の広さは足りているか
7. ⑧完成の「眺める間」（UIが3秒後に消えて、ブーケだけが残る）を入れるか

**見せ方について**

8. App Store 5枚の物語（1枚目は説明せず空気だけ／3枚目で花言葉を見せる）でよいか

ここが決まってから、②のワイヤーフレームを詰め、最後に実装へ移ります。
